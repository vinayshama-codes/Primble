
A correct ACORD 125 has every applicable field completed, every underwriting question answered, and non-applicable/unsupported fields left blank rather than guessed.
I found something especially useful for what you are trying to establish: Vertafore publishes an actual completed field-mapping example of the ACORD 125 (2025/03) showing the current form, field by field, across all four application pages. Vertafore identifies ACORD 125 2025/03 as the newer edition, replacing the prior 2016/03 edition in its current commercial-lines forms implementation. (VertaFore Help)
The four pages of the current form look like this structurally:
Page 1 — Producer/policy / applicantProducer and agency information → Carrier/NAIC → Transaction status → Lines of business → Attachments → Proposed policy dates/billing → First Named Insured → legal entity → address → FEIN → SIC/NAICS/GL code → phone/website → other named insureds.
Page 2 — Contacts/premises / operationsInspection and accounting contacts → every premises/location → owner/tenant → employees → revenue → square footage → description of operations → nature of business → date business started → detailed primary operations → installation/service percentages where applicable → other named insured operations → additional interests.
Page 3 — General underwriting informationQuestions 1–15 → subsidiaries/parents → safety program → hazardous materials → other insurance → cancellations/non-renewals → abuse/negligent hiring claims → fraud/arson → code violations → bankruptcy → judgments/liens → trusts → foreign exposure → uncovered ventures → drones → prior carrier information.
Page 4 — Losses and signaturesPrior carrier continuation when required → loss history → years of history → paid/reserved/open/subrogation information → total losses → producer signature/name/license/NPN → applicant signature/date and applicable fraud notices.

And this is where I think Primble needs a very clear rule:
Blank ≠ No.
If the source material does not establish the answer to Question 9, Primble cannot check N merely because it found no bankruptcy reference in the declarations.
The correct output should instead be:
Question 9: Unverified — insured confirmation required.
Then the client questionnaire resolves it before Primble produces the submission-ready 125.
That difference is fundamental.

The important conclusion for Primble
I would build the scoring against four states for every material ACORD field, not “filled versus blank”:
VERIFIED — source supports the value exactly.CONFIRMED — insured answered it through Primble.NOT APPLICABLE — intentionally blank.UNRESOLVED — information is needed before submission.
What you do not want is a fifth state:
ASSUMED.
That is where your hallucination/data-transfer problem starts.
